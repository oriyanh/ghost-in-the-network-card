# DPU Traffic Hijacking (Research PoC)

A research-oriented proof-of-concept repository for experimenting with traffic interception and HTTP/HTTPS redirection behavior on NVIDIA BlueField-2 + DOCA/DPDK environments. This repository supports my MSc thesis, <b>"Ghost in the Network Card: Stealthy Attacks from a Compromised DPU"</b> (link to be added later).

The codebase combines:
- A packet-processing datapath (`traffic-dump`) built with DPDK flow rules.
- Nginx-based “victim/attacker/staging” web endpoints for controlled experiments.
- Setup notes/scripts for host and DPU machines.
- Small Python utilities for cookie/session behavior tests.

> ⚠️ **Important**
> This repository is intended for authorized lab testing only. Use it only in environments where you have explicit permission.

---

## Repository Structure

- `traffic-dump/` – DPDK C application that inspects/forwards/drops traffic and can modify HTTP redirect payloads.
- `nginx/` – Web content and Nginx configs for:
  - `victim/` - used to setup a "victim" server on azure, strictly for acquiring a certificate from LetsEncrupt
  - `attacker/` - setup for attacker server on azure. Should acquire certificate from LetsEncrypt.
  - `stavro/` - Actual victim server, attached to Bluefield2 DPU. Includes `auth_service.py` for simple login flow. Needs the certificate generated by the azure "victim" server
- `config/` – Setup scripts and host/DPU notes:
  - `stavro/` – BlueField/DOCA/OVS setup scripts and recorded defaults.
  - `largo/` – Victim client machine setup and `wrk` benchmark helper.
- `docs/smartnic.md` – Curated external references for BF2/DOCA/OVS/offload topics.
- `simple_server.py` / `simple_client.py` - Minimal cookie/session demo tools. Used to test that TLS offload works and communication works between stavro/largo
- `genereate_regex.py` – Helper utility to generate byte-pattern rules for `sessionId` matching.

## What `traffic-dump` Does

`traffic-dump/main.c` currently:
- Initializes DPDK ports and flow rules for HTTP (`80`) and HTTPS (`443`) traffic.
- Tracks source IPs with a timer-backed hash map.
- Applies staged forwarding/drop logic for HTTPS SYN traffic.
- Detects HTTP 301 responses and attempts in-place `Location:` domain replacement (compile-time flag controlled).
- Includes optional hooks for JavaScript/header injection paths (via macros).

Build-time feature flags in `traffic-dump/Makefile` currently include:
- `-DINTERCEPTREDIRECT` -- Used to indicate that plaintext HTTP redirects need to be intercepted and modified. Used in conjunction with the following flags:
- `-DWORDSWAP` -- swaps the first 2-byte aligned two bytes in the Location header with the next two bytes. If the first 2-byte sequence is equal to the next sequence, skip ahead. Preserves checksum, no need to recalculate
- `-DCSUM_OFFLOAD` -- indicates that checksum calculation should be offloaded to hardware.
- `-DSAME_LENGTH_DOMAIN_SWAP` -- swaps Location URL with evil URL that is of the same length
- `-DNEW_DOMAIN_SWAP` -- swaps Location URL with evil URL of arbitrary length

## Prerequisites

### Packet path / DPU path
- Linux machine(s) with DPDK-compatible NICs (BlueField-2 setup is assumed by scripts).
- Installed DPDK development packages (`pkg-config --exists libdpdk` must pass).
- Root/sudo access for hugepages, NIC config, and raw packet processing.

### Python utilities
- Python 3.9+
- Packages:
  - `flask` (for `simple_server.py`, `nginx/stavro/auth_service.py`)
  - `requests` (for `simple_client.py`)

Install:

```bash
python3 -m pip install flask requests
```

## Quick Start (Software Utilities)
This should be done after installing all utilities, SDKs and dependencies on largo (victim client), stavro (victim server), and DPU (attached to victim server).

Run the simple cookie/session demo first (no DPDK required):

1. Edit bind addresses if your host does not own `10.10.1.1`.
2. Start server:

```bash
python3 simple_server.py
```

3. In another terminal, run client:

```bash
python3 simple_client.py
```

You should see request/response headers and rotating `sessionId` values.

## Build and Run `traffic-dump`

From repo root:

```bash
cd traffic-dump
make
```

Binary output:
- `build/traffic-dump-shared`
- symlink `build/traffic-dump`

Run with DPDK EAL arguments (example):

```bash
sudo ./build/traffic-dump -l 1 -n 1 -a 03:00.0,representor=[0,65535] --socket-mem=1024
```

Notes:
- The app expects at least **2 EAL-probed ethdevs** (e.g., via `-a ... representor=[...]`) and currently uses ethdev index `0` as RX and `1` as TX.
- Hugepages and NIC binding/permissions must be configured before execution.

## Nginx Experiment Assets

- `nginx/victim/` and `nginx/attacker/` provide static login/success pages and baseline Nginx configs.

These scripts are lab notes/scripts and may require adaptation to your distro, interface names, and hostnames.

## Suggested Workflow

1. Validate software pieces locally (`simple_server.py` / `simple_client.py`).
2. Stand up victim/attacker Nginx endpoints.
3. Prepare DPU/host networking + DOCA/OVS according to `config/stavro/*`.
4. Build and run `traffic-dump`.
